# 起動済み画面への復帰（Issue #13、開発中）

二度目の`run`が起動ロックに当たった場合、起動中のインスタンスが保持する専用プロファイルと起動時の作業フォルダーを使ってVS Codeを開く。設定再生成・要求再送・プロセス停止・ロック復旧は行わない。明示的な作業フォルダー指定は存在と実保存先を確認し、同じ専用プロファイルで開く。後からVS Code内で切り替えた最終アクティブフォルダーを追跡する機能ではない。

## 所有確認

- 初回の画面起動後に、ロック所有者と起動計画をローカルの`bridge.lock/desktop.json`へ排他的に保存する。
- 接続プロセスは、その時点の変更不能なスナップショットのSHA256を保持する。
- 再実行側は毎回32バイトの乱数を生成。ループバックの`/desktop-instance?nonce=...`へ送り、既知の接続キーによるHMACを照合する。生の接続キーや作業パスをこのHTTPで送受信しない。
- 署名は用途・乱数・スナップショットに束縛する。過去の応答や書換済みローカル情報は流用できない。
- PID生存、所有者との一致、照合前後のローカル情報不変、専用プロファイルの実パスを確認する。未準備・旧版・偽応答・別プロファイルなら停止する。
- この経路もHost/Origin検査を通す。推論キューを使わず、返すのは照合値だけで、実行コマンドを受け付けない。同じユーザーのキーを読めるローカルコードからの隔離や、確認直後のプロセス終了を防ぐ仕組みではない。

## 現時点の検証

165テスト成功。実HTTPで偽証明、応答再利用、メタデータ改変、所有者切替、別プロファイル、準備途中、ブラウザーOriginを拒否した。実行中の模擬推論を中断・再送しないことも確認。作業フォルダー削除や不正な所有者情報は、内部エラーではなく状態に合ったエラーを返す。

別のテスト用プロファイルで実VS Codeを起動し、実CLIの`run`を再実行すると正常終了し、同じworkspaceウィンドウを再利用した。設定2ファイルはハッシュ不変。新たに現れた小さなウィンドウはサインイン画面上のツールチップで、別のworkspaceではなかった。テスト専用ウィンドウと接続プロセスは終了した。

この実機試験の初回起動は、Edge起動を省いたテスト用接続サーバーによるもので、M365へ送信していない。新規プロファイルにVS Codeのサインイン案内が出た。後続の観測では空のチャット入力画面になっていたが、案内を閉じた経路は検証記録にない。既存チャット履歴への復帰、実M365推論継続、別workspace指定の実画面は未確認。現段階では未公開。

9c2fd9dの配布候補をローカル更新チャネルへ配置し、実際のM365Relay.cmdから本体取得・同梱Nodeによる検証・再表示まで正常終了。その後のキャッシュ再利用でも同じworkspaceウィンドウを維持し、設定/キー/所有者情報/作業ファイルの計7ファイルがハッシュ不変。起動済みの所有者は上記テスト用接続サーバーであり、初回から実M365へ接続した全工程の検証ではない。

## 実M365と履歴の追加確認

同じ独立プロファイルの接続サーバーを実M365バックエンドへ接続し、要求台帳のsending状態を観測してから配布M365Relay.cmdを実行。再表示は正常終了し、元のM365要求も約14.5秒で指定回答に到達した。この要求はHTTPから開始した試験であり、チャットUIからの送信とは区別する。

続いて実VS Codeから短い試験会話を送信し、実M365の回答を表示。その後ランチャーを再実行しても同一ウィンドウに同じ会話を維持し、設定/キー/要求台帳/所有者情報の7ファイルがハッシュ不変だった。明示的な別workspace指定は独立ウィンドウになり、引数なしの再実行では起動時workspaceの元の会話に戻った。既存の一般プロファイルのウィンドウは維持。試験用2ウィンドウと接続プロセスは終了した。

初期のモデル一覧はAutoのみだったが、モデル管理の操作後にはM365Relayが表示され、送信できた。自動的な読み込み完了と操作の効果は切り分けていない。これは初回セットアップの残課題で、再表示の照合処理の成功と混同しない。M365は既に認証済みの専用Edgeを使用し、未認証からの全工程は未検証。
