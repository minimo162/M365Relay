# 配布版の新規作業起動

fd7dcc312f57のZIPを.local/fresh-layout-checkへ新しく展開し、同梱Run.cmdから未使用のfirst-layout-20260908フォルダーを開いた。既存の専用認証・VS Codeプロファイルを使用しており、未認証の新規利用者テストではない。

実画面で左ファイル一覧、中央Welcomeのチャット入力欄1つ、右サイドバー非表示を確認。手動でパネルを閉じる操作なしに初期配置が成立した。専用設定はeditor/chat/chat.editor.fontSize=16、window.zoomLevel=1。

新しいフォルダーはRestricted Modeになった。ここでは信頼設定を操作せず、チャット実行は行っていない。既存フォルダーの信頼状態を新規フォルダーの信頼と扱わない。

旧配布サーバーをexec経由でCtrl+C終了した後、プロセス32100と8731の待受が消失したがbridge.lockが残り、Run.cmdがalready_runningで終了した。停止確認後に同梱Nodeからrecover-lockを実行すると起動できた。これは観測ツール経由の終了であり、実コンソールでのCtrl+Cの同一挙動は未確認。

現行state.mjsは再起動前のロックのみ自動回復し、同一起動中に異常終了したPIDのロックは手動recover-lockが必要。一般利用者向けの復旧導線が残課題。生存プロセスや判定不能なロックは維持し、並行起動の競合と要求台帳の保持も検証してから改善する。

新配布サーバーの診断ログはlogs/run-e44ecf11-1f74-4f28-9811-b7da3edb4d79.jsonl。未認証初回導線、Restricted Mode後の利用者操作、毎回の保存済み配置の強制変更は本試験で検証していない。
