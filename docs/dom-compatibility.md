# M365Relay 0.2.15 — 実M365互換性と検証範囲

## 実機で確認した差分

2026-09-07の実VS Code＋実M365検証で、次の画面・応答差分を確認しました。

1. 入力済み文字が`A`や`SPAN contenteditable="false"`へ再構成される。
2. `aria-hidden`装飾SPANが入力欄内へ現れる。
3. 85k文字級の一括入力後、全文は入っていても送信ボタンの有効化が遅れる。
4. `BRIDGE_FINAL` / `BRIDGE_TOOL`の`_`が`\_`へMarkdownエスケープされる。
5. 制御形式の改行が空白へ畳み込まれ、最終回答やツール呼び出しが1行になる。
6. JSON文字列へWindowsパスや`python -c "..."`を埋めるとM365が引用符を正しくエスケープしない場合がある。
7. PDFを`read_file`した後、同じ目的のPython/pypdf端末実行を言い換えて繰り返す場合がある。

## 入力側の安全条件

`src/dom.mjs`は、表示上の段落・改行・空白・タブ・NBSPを区別して入力本文を読み取ります。
許可済みのインライン要素は子テキストだけを読むため、href・aria-label等の属性値は本文へ混ぜません。
`hidden` / `aria-hidden`の装飾は表示本文から除外します。その結果で期待全文と一致しなければ送信しません。
IMG/BUTTON等の未知の非テキスト要素はfail-closedです。

長大入力はクリップボードを変更せず`Input.insertText`を1回だけ実行します。
入力後、送信可能待ち、送信直前に全文一致を確認し、欠落・変化があれば再入力・自動再送せず停止します。
送信ボタンの準備が遅い場合は、全文一致を維持したまま最大15秒読み取り待ちします。

## 応答transport

ツール呼び出しは`BRIDGE_TOOL`、最終回答は`BRIDGE_FINAL`の生テキストtransportを優先します。
制御語だけは`_` / `\_`を同一視し、制御語間の空白・改行のどちらも受理します。
最終回答本文、CONTENT本文、ARG本文はグローバル正規化しません。

ツール名は今回VS Codeから渡されたものに完全一致する必要があります。
ARGから再構築した引数は、元のVS Code JSON Schemaで検証します。
旧JSON transportも後方互換用に残しますが、任意の壊れたJSONを推測補修しません。壊れたWindowsパスを直すために本文全体を走査すると、別の正常な文字列を変更できるためです。

完全コピー・複製を依頼された場合は、M365で本文を再生成させず、VS Codeから同梱Nodeの`src/cli.mjs copy-verify`を実行します。これは元ファイルをデコードせずに新規ファイルへコピーし、両方を読み戻してバイト数とSHA-256を比較します。

## ループ防止

累積ツール回数の一律上限は設けません。要求ごとの1応答1ツール、送信前の入力一致、応答の完全検証、結果不明要求の自動再送禁止を維持します。
M365向けプロンプトにも、Python/pypdf/PyMuPDF/pdftotext等を存在前提にしないこと、同じ失敗依存関係を言い換えて繰り返さないことを明記しています。

## 診断

公開診断は固定列挙の処理段階・DOM理由・既知タグ・文字数・ツール回数などに限定します。
依頼本文、M365回答本文、DOM HTML、URL、selector、ブラウザー内部例外、stack、ツール引数、接続キーは公開エラーやdiagnosticへ載せません。

## 検証

通常の`node --test`で契約・プロトコル・診断・状態管理を検証します。
`integration/editor.chromium.mjs`は実Chromium/CDP上の合成入力欄を使い、リンク化、readonly SPAN、aria-hidden、長大入力、遅延DOM、送信直前変更などを回帰検証します。
`integration/fixtures/dom-0.2.2.mjs`は旧readerの再現用fixtureです。

実機では通常会話の往復とVS Code標準ツールの実行開始まで確認済みです。
組織ごとのM365 DOM変更、入力上限、PDF抽出能力、社内EDR、複数ラウンドの業務完走は継続受入対象です。
