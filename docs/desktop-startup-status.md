# VS Codeの起動状態

起動要求の受付と、ウィンドウの存在を区別します。VS Codeの指定プロセスを読み取り専用で観測し、既存ウィンドウや更新プロセスを終了しません。

- `window`: 指定実行ファイルのプロセスにウィンドウがあることを確認。M365サインインやモデル準備の完了までは意味しません。
- `handoff`: 起動側プロセスが正常終了。既存プロセスへの引き渡し等があるため失敗扱いしませんが、ウィンドウ確認とは区別します。
- `failed`: 起動側プロセスが非ゼロで終了。終了コードを表示します。
- `unconfirmed`: 観測できない、または約35秒でウィンドウを確認できない状態。起動成功を断定しません。

通常はウィンドウ確認または起動側の終了で待機を終えます。固定時間いっぱい待つ方式ではありません。観測用PowerShellだけを終了処理の対象とし、VS Codeは強制終了しません。

診断ログの`desktop_launch`には`desktop_status`と数値の`exit_code`を保存します。プロセスの生のエラー、実行パス、ユーザーの本文は保存しません。

新規接続では画面を確認できなくても接続サーバーを維持します。更新完了後などに起動ファイルを開き直せます。既存接続への再オープンが失敗・未確認の場合は、起動側へ非ゼロを返して結果を表示します。

検証状況: 制御した子プロセスによる正常終了/異常終了/観測失敗、既存ウィンドウの読み取り、実際の更新中異常終了を確認。更新後のVS Code 1.136.2では、起動監視部分が902msでwindowを返し、Bridge.cmd runによる再オープンは終了コード0・3345msで同じウィンドウへ戻ることを確認しました。M365の認証時間を含む値ではありません。

監視対象は起動確認までです。ウィンドウ確認後の長時間監視やクラッシュ復旧を行う機能ではありません。

## 専用VS Codeの状態表示

新規専用プロファイルでは、同梱の小さな拡張がステータスバーに`M365Relay: 起動中`などの観測状態を表示します。クリックすると、サーバー・M365・指定モデルの直近状態を表示します。

- `起動中`: Relayは稼働していますが、M365のサインインとモデル選択はまだ確認していません。
- `サインインが必要`: M365画面がサインイン要求を返しました。専用Edgeでサインインしてから新しい依頼を開始します。
- `利用可能`: 実際の要求でM365応答とGPT 5.6 Think Deeperの選択確認まで成功しました。
- `結果未確認`: 送信後の応答を完全検証できませんでした。自動再送せず、画面と診断ログを確認します。
- `停止`: `/health`へ接続できません。起動ウィンドウと作業フォルダーを確認します。

`/health`の`status`はRelayプロセスの稼働状態だけを示します。`live_verified=false`のままでは、M365やモデルが利用可能だとは表示しません。状態情報は専用プロファイル内だけで使い、通常のVS Code設定やDBは変更しません。

送信を伴わない`diagnose`では、専用Edgeの所有確認、M365ページの観測、サインイン要求、指定モデル未確認を別々に返します。`m365_state=m365_page_observed`はページの観測であり、モデル選択や業務成果物の成功を意味しません。モデルは実要求の送信前選択確認を通過した場合だけ`verified`になります。
