# 実用化の完了条件

ユーザーの目標：誰でも簡単に設定・実行可能な、高速で動く実用性のあるアプリ。
必須制約：既存のM365 Copilot契約と画面操作のみ。追加のモデルAPI契約を前提にしない。

この目標は進行中。以下を一部のテスト成功で置き換えない。

## 初回利用

- 配布ZIPから利用者のnpm install、PATH編集、管理者権限なしで起動できる。
- 接続キーやJSON設定を利用者が手作業で編集せず、対応するVS Code環境へ接続できる。
- サインインが必要な場所、接続状態、開始・停止・復旧の操作が明確である。
- 更新で既存の設定・認証・ユーザーファイルを破損しない。
- 開発環境のソース直接起動を配布物の実証に代えない。

## 正しさと継続性

- 日本語、パス、引用符、改行、空白、コードを実画面の往復で保つ。
- 読取→複数ファイル編集→実成果物検証→必要な再修正を完走する。
- 会話圧縮後も目的、禁止事項、実行済み操作を取り違えない。
- 上限超過、停止、送信結果不明、同じ失敗の反復を適切に扱う。
- VS Codeによる承認・実行を保ち、搬送テキストを権限や実行証拠にしない。
- 小さな合成課題の成功だけで任意業務や会社環境の成功を主張しない。

## 速度

- 基本往復、複数ファイル課題、圧縮を含む継続課題を個別に計測する。
- 送信準備、実M365生成、応答安定待ち、ツール実行、全体時間を分けて改善箇所を特定する。
- 正確な入力照合や未完の応答の拒否を外して速く見せない。
- 不要なツール定義、同じファイルの不要な再読取、冗長な応答、不要な待機を減らす。
- 変更前後の同一課題で、完走率、経過時間、モデル往復数、介入回数を比較する。
- 「高速」の具体的な受入値は、同一課題の正常完走の基準値が取れた時点で設定する。現在の失敗走行の短さを基準にしない。

## 現在の優先順位

1. 文字列の搬送と実M365コード表示読取を修正し、固定課題を通す。
2. 入力が空へ戻る失敗の原因を特定する。
3. 正常完走の時間内訳を取得し、往復数と待機を改善する。
4. 初回接続設定を統合し、配布ZIPの初回利用・更新・復旧を実機検証する。

実機証拠は `context-feasibility-2026-09-08.md` と各修正検証記録へ残す。
