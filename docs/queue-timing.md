# 要求の順番待ち時間

診断ログは要求本文・応答本文・ツール引数・認証情報を保存せず、要求IDと数値を記録します。

- `queued`: 先行要求があるため待機列へ入る時点。`queue_depth`はその時点の待機位置（処理中の1件を含まない）です。待機列が満杯で拒否された要求には出ません。
- `accepted.queue_wait_ms`: 要求の準備後、処理枠を取得するまでの時間です。台帳確認やM365の処理時間は含みません。
- `error.queue_wait_ms`: 待機中に中止された場合は中止までの待機時間です。処理枠取得後のエラーでは、取得までの時間を保持します。準備前のエラーにはありません。
- `backend_timing.total_ms`: 処理枠取得後のM365接続・添付・生成・応答検証などの時間です。

ミリ秒は単調増加する時計で計測し、整数へ丸めます。起動ウィンドウには待機時に「先行する要求の完了を待っています。」と表示します。

後続要求の待機は先行要求の処理と重なります。すべての`queue_wait_ms`と`backend_timing.total_ms`を足して全体所要時間にしてはいけません。全体時間は最初の開始から最後の完了までを別に確認します。

この記録は観測用です。処理順序、重複防止、待機数上限、キャンセル動作、M365への送信回数は変更しません。
