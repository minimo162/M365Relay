## A. GitHubアカウントなしでの入口

- GitHub未サインインの VS Code で Custom Endpoint が設定できる。
- Local / Agent のモデル一覧に m365-copilot-ui が出る。
- 主モデルと補助モデル・自動選択を混同しない。GitHubへのサインインを要求する別機能を検証対象にしない。
- 手動サインイン済みの専用Edgeに対して diagnose が成功する。
- 他のEdgeプロファイルが同じポートを使っているときは、勝手に使用しない。

## B. 読む → 作る → 読み直す

非機密テスト用の sample.txt と空の出力先を用意する。
「3行に要約して summary.md へ保存し、保存後に読み直して確認」を依頼する。
VS Code が送る実ツール名と引数の定義、M365の返答、VS Codeの実ツール履歴、実ファイルを対応付ける。
ツールの出自がVS Code標準であることも選択画面で確認する。
チャットの「保存しました」だけで成功にしない。

## C. 任意の目的への追従

同じ接続のまま「作った要約の2行目だけを別の表現に変更し、差分を確認」を追加依頼する。
変更前に必要な内容が読まれ、実際の結果に基づいて次のツールが選ばれること。
CSV専用ロジック、手で作った固定ツール列、偽の結果を使わない。

## D. 特殊文字の忠実性

次を含む内容を読み書きし、変更前後をbyte比較する。

```text
C:\Test\日本語\a_b*[x].txt
"quoted" & <tag> #hash |pipe| ~tilde~ `tick`
改行、タブ、絵文字😀、連続したバックスラッシュ\\
```

M365の画面表示でバックスラッシュやMarkdown記号が消えないこと。
JSONのschema検査だけでは文字内容の正しさを証明できないため、元ファイルと再読取結果も比較する。
折り畳み・コードブロック行番号・途中省略が起きた場合は受理してはいけない。

## E. 停止と不明状態

入力途中、送信直後、回答待機中、ツール承認待ち、ターミナル実行中で停止する。
M365への二重クリック、別タブの停止、次の勝手なツール呼び出しがないこと。
既に実行されたツールと未実行のものを区別し、ロールバック済みと誤表示しない。
接続を切って再開した際、過去回答を別の会話に流用しないこと。

## F. 入力上限・未対応形式

長い履歴・多数のツール・対応画像では、搬送と内容の保持を確認する。
上限超過・非対応画像形式・未対応スキーマはM365へ送る前に明示エラーになり、入力の一部だけを勝手に送らないこと。
まずは選択ツールを少なくして動作を確認し、その後標準ツールの種類を増やす。

## G. 同時要求・再起動

異なるチャットA/Bを続けて送信し、要求と回答を取り違えないこと。
タイトル生成等を本モデルに設定した場合も、主処理と補助処理を混同しないこと。
送信後にプロセスを落として再起動し、requests.jsonに残った不明な要求が自動再送されないこと。
`requests.archive.jsonl`へ移した完了・結果不明要求の指紋が再起動後も重複判定に使われ、送信中の記録しかない場合は`ledger_full`で停止すること。
全く同一の別依頼はこの版では止まり得る。その使い勝手を受入判断に含める。

## 記録の項目

コードの版とSHA256、各アプリの版、選択ツールの定義、依頼、実際のツール結果、生成されたファイルのハッシュ、経過時間、生成回数、人の介入回数、成功/失敗/結果不明、必要な修正。
機密データやM365の資格情報をリポジトリに保存しない。検証用の非機密フィクスチャを使う。
