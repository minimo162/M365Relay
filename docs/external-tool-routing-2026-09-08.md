# 実VS Codeでの外部ツール依頼検証（2026-09-08）

## 再現した失敗

公開0.2.19で新規の実VS Codeチャットから3ファイル修正を依頼した。最初は接続プロセスが停止しておりnet::ERR_CONNECTION_REFUSED。待受プロセス不在を確認し、停止済みロックを正規手順で回収して再起動した。M365送信前の失敗であったため再試行した。

M365は51ツールのTXTを読んだものの、この画面にネイティブツールとして登録されていないことを理由に作業を断った。本文28983文字、18310ms、最終回答で停止。此前の名前指定tool_choiceによる短いHTTP試験では、この自動選択時の誤認を検出できていなかった。

## 修正候補

本文の先頭と末尾で、M365の役割は外部VS Codeへ渡す実行依頼データを生成することであり、M365内で関数を直接実行する必要はないと明示。BRIDGE_TOOLを返すと外部VS Codeが承認・実行して結果を次回返すことを説明する。Schema検証、tool_choice、実際の拒否、承認の扱いは変更しない。
