# 実文字数超過とクライアント圧縮の接続調査

現在は入力28000 tokensをVS Codeへ申告し、M365へ送る完全なprompt.lengthを120000で制限する。実ランaccepted23件は100296〜117266文字。超過を検出したRelayは413/context_too_largeで送信前停止し、自動要約や再送は行わない。

インストール済みVS Code a44adf7f53のextensions/copilot/dist/extension.jsを確認した。context_length_exceededを含む文字列から容量超過を判定するTltは検索サブエージェントの経路で使用され、1回だけ安全係数を下げてpromptを再構成する。通常チャットの一般badRequest/failed処理はエラー応答を設定する経路が存在する。

この検索は通常チャットの全分岐を完全に証明するものではない。ただしRelayのエラー名をcontext_length_exceededへ変えれば通常チャットが自動compactする、とする根拠にはならない。現時点ではその変更を採用しない。

次の検証は、隔離したクライアント要求で容量超過応答後の再要求の有無・内容を観測すること。実M365へ上限超過本文を送る必要はない。エラー後の再構成がなければ、申告予算の調整またはクライアント側の連携が必要。どちらも文字列切捨てや要約文を実行証拠として扱う変更は行わない。

ユーザー提示の128000文字という入力欄の限界は今回独立検証していない。120000文字の現行送信上限を維持。文字数厳密連動の自動compactは未実装であり、全体実用化目標は継続中。

## 通常チャットでの実クライアント試験

専用モデルのURLだけを一時的にlocalhost:8732へ向け、上流へ転送しない試験サーバーから413/context_too_largeを返した。既存の信頼済みworkspaceで新しい通常チャットを作り、ツール不使用の短い診断要求を送信。2026-09-07T21:26:22.458Zに90481 bytesの要求1回を観測した。

実画面はRequest Failed: 413とTry Againを表示して終了し、観測中に追加の再要求やcompact表示はなかった。小さい新規会話へ容量超過を模擬した試験であり、すべての履歴量・別エラーコード・検索サブエージェントの挙動を証明しない。現行413だけで通常チャットが自動圧縮する、という期待には反証となる。

試験後にURLをlocalhost:8731へ復元し、試験サーバーを停止。モデルの認証ヘッダー・要求本文は記録していない。製品の120000文字上限・28000トークン申告は変更なし。
